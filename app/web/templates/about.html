A MORE INCLUSIVE WEB STARTS HERE

Accessibility.
With clarity.

AccessLens helps students, developers and teams find common accessibility barriers in public web pages, understand the evidence, and plan improvements.

01 / PURPOSE

What does this program do?

It opens a public URL in a real Chromium browser, evaluates the rendered page with axe-core, and saves an element-level report. You can inspect affected HTML, WCAG criteria, severity, suggested fixes and a screenshot.

The dashboard summarizes completed scans. Reports can be exported as PDF, editable Word, legacy DOC, CSV or JSON.

02 / EVIDENCE

Why can a major website have findings?

A popular website can still have accessibility barriers. Results also depend on the exact page, viewport, loading state, region, consent dialogs and the visitor's session.

Inspect the screenshot and element evidence. A finding on one page is not a verdict on an entire company or website.

03 / INTERPRETATION

Three kinds of results

  • Confirmed findings: automated WCAG rule failures. These affect the heuristic score.
  • Manual review: incomplete or inconclusive checks. These do not reduce the score.
  • Best practices: recommendations beyond the selected WCAG rules. These do not reduce the score.

If axe-core cannot run, coverage is clearly marked “Basic checks”. An empty result under limited coverage is not a full accessibility pass.

04 / SCORING

A useful indicator, with limits.

The score starts at 100. Each distinct failed rule deducts its highest severity weight: critical 10, serious 7, moderate 3, minor 1. Repeated elements add 25% per additional occurrence, capped at five occurrences per rule (2× the weight).

Only confirmed findings affect the score. Best practices and review items are excluded. The score is clamped to 0–100. It is not a percentage of WCAG compliance or a Lighthouse score.

05 / SCOPE

What still needs a human?

Test keyboard navigation, screen reader announcements, task completion, meaningful text alternatives, captions, zoom, responsive states and dynamically opened menus. One desktop page scan cannot establish full WCAG conformance.

AccessLens does not log in, solve anti-bot challenges, accept consent, submit forms or crawl an entire website. HTTP error pages and recognizable bot challenges produce a failed scan rather than a misleading score.
